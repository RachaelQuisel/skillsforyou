# Plain-English project communication

## Trigger

I use this skill to explain project information without requiring the reader to understand the underlying database.

A status update, dashboard label, report, or project explanation needs to be understandable to its audience.

## Inputs

- The original content and verified numbers.
- The intended reader and format.
- The baseline and comparison period for any reported change.

## What happens

1. Choose the appropriate structure for the format.
2. Preserve the user’s terminology.
3. Give each number its unit, population, and relevant context.
4. Explain comparisons without dropping the baseline.
5. Replace internal terminology with readable descriptions.
6. Remove unrequested recommendations and unsupported claims.

## Outputs

Revised copy matched to its destination, such as a short message, sprint bullet, dashboard caption, or longer explanation.

## Try it with a fictional example

Once the source skill is installed and configured, use a request like this:

```text
Use plain-english-project-communication to rewrite this fictional dashboard label: 18 of 24 equipment inspections are complete for September. Preserve the counts and period.
```

## Setup and limits

The skill rewrites supplied information; it does not independently measure performance. Technical identifiers stay out of audience-facing copy. Use fictional or approved examples when sharing an output.
