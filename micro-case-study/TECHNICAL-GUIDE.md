# Micro case study

## Trigger

I use this skill to describe one specific piece of value from a project. Each case focuses on a single improvement that can be explained and checked.

Transcripts need to be reviewed for completed improvements or agreed work that remains unfinished.

## Inputs

- Source transcripts and supporting evidence.
- Completion status and any verified time or cost measurements.
- Existing case records for duplicate checks.

## What happens

1. Identify individual improvements rather than summarizing an entire project.
2. Separate completed, adopted work from queued work.
3. Describe the problem, intervention, and outcome.
4. Distinguish measured benefits from projected benefits.
5. Prepare the headline, tags, and supporting record fields.
6. Check for an existing case before creating a configured destination record.

## Outputs

Structured case-study records labeled Completed or Queued, with language that matches the evidence.

## Try it with a fictional example

Once the source skill is installed and configured, use a request like this:

```text
Use micro-case-study to draft a case from this fictional inventory workshop. The new form is planned but not deployed. Keep the case marked Queued.
```

## Setup and limits

This public version returns drafts by default. Saving to a record system requires an explicitly authorized destination and a verified schema. Outreach is outside this skill.
