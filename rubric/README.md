# Rubric

## Trigger

I use this skill to make the standard for a good plan explicit before accepting the first draft.

A plan, specification, or project-tracking design needs a structured review and revision.

## Inputs

- The goal, source material, and relevant constraints.
- The initial plan or enough context to draft one.

## What happens

1. Research the relevant source material.
2. Write the initial plan or specification.
3. Define criteria that are specific to the task.
4. Grade the draft against those criteria.
5. Identify weaknesses and revise the plan.
6. Show the criteria, initial grade, changes, and final plan.

## Outputs

A revised plan with a visible explanation of how it was assessed.

## Try it with a fictional example

Once the source skill is installed and configured, use a request like this:

```text
Use rubric to review a fictional equipment-maintenance tracking plan. Evaluate whether responsibilities, deadlines, evidence of completion, and exception handling are clear.
```

## Setup and limits

For project-tracking tables, review duplicate handling, consistent row scope, useful views, ownership, and evidence for status claims. A self-assigned grade is a review aid, not an independent quality measurement or proof that the plan works.
